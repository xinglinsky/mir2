### 阶段 2：Rust 服务器端 i18n 模块实现（优先级 P1，预计 1 周）

#### 2.1 创建 i18n 模块（2-3 天）

**目标**：实现统一的消息本地化系统

**任务清单**：
- [ ] **创建 `crystal-server-core/src/i18n.rs`**
  ```rust
  pub struct I18n {
      translations: HashMap<String, String>,
      language: String,
  }
  
  impl I18n {
      pub fn new(language: &str, config_path: &Path) -> Result<Self>;
      pub fn msg(&self, key: &str, args: &[&dyn Display]) -> String;
      pub fn get(&self, key: &str) -> Option<&String>;
  }
  ```

- [ ] **实现语言文件加载**
  - 支持从 `Configs/Language.ini` 加载（兼容 C# 格式）
  - 支持从 `i18n/zh-CN.toml` 加载（Rust 原生格式）

- [ ] **实现消息格式化**
  - 支持 `{0}`, `{1}` 等占位符
  - 支持数字格式化（如 `{0:#,##0}`）

**验收标准**：
- 模块能够正确加载语言文件
- `msg()` 函数能够格式化消息

## 四、风险评估与缓解

### 4.1 技术风险

**风险 1：翻译数据量大，人工翻译耗时**
- **缓解**：优先翻译高频内容，使用工具辅助批量处理
- **缓解**：建立翻译模板和规范，提高效率

**风险 2：Rust i18n 模块性能影响**
- **缓解**：使用 HashMap 实现 O(1) 查找
- **缓解**：启动时一次性加载，运行时无 IO
- **缓解**：进行性能测试和优化

**风险 3：翻译不一致导致用户体验差**
- **缓解**：建立翻译规范和术语表
- **缓解**：进行一致性检查和人工审核

### 4.2 进度风险

**风险 1：翻译工作量超出预期**
- **缓解**：按优先级分阶段实施
- **缓解**：先完成核心内容，后续逐步完善

**风险 2：Rust i18n 实现复杂度高**
- **缓解**：参考 C# 实现，保持架构一致
- **缓解**：分模块逐步替换，降低风险

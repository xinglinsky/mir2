# Rust 客户端/服务端测试运行指南

## 一、测试类型

项目中有两种类型的测试：

### 1. 单元测试（Unit Tests）
- **位置**：各个 crate 的 `src/` 目录中，使用 `#[cfg(test)]` 标记
- **主要位置**：
  - `crystal-shared-proto/src/*.rs` - 协议编解码测试
  - 其他 crate 中的测试模块

### 2. 集成测试（Integration Tests）
- **位置**：`crystal-server-core/tests/` 目录
- **类型**：Golden tests（对比测试）
  - `golden_drops.rs` - 掉落系统测试
  - `golden_npc_expand.rs` - NPC 扩展测试
  - `golden_quests.rs` - 任务系统测试
  - `golden_recipe.rs` - 配方系统测试
  - `golden_routes.rs` - 路径系统测试

## 二、运行测试命令

### 2.1 运行所有测试

```powershell
# 在 RustServer 目录下运行
cd RustServer
cargo test --workspace
```

### 2.2 运行特定 crate 的测试

```powershell
# 运行 crystal-shared-proto 的所有测试
cargo test --package crystal-shared-proto

# 运行 crystal-server-core 的所有测试
cargo test --package crystal-server-core
```

### 2.3 运行特定测试

```powershell
# 运行包含特定名称的测试
cargo test --package crystal-shared-proto test_item_encode_decode

# 运行 golden tests
cargo test --package crystal-server-core golden
```

### 2.4 运行测试并显示输出

```powershell
# 显示测试中的 println! 输出
cargo test --workspace -- --nocapture

# 显示所有输出（包括通过的测试）
cargo test --workspace -- --show-output
```

### 2.5 运行测试并更新 Golden Files

```powershell
# Golden tests 通常需要环境变量来更新参考文件
# 查看具体测试文件了解如何更新
$env:UPDATE_GOLDEN="1"
cargo test --package crystal-server-core golden
```

## 三、测试选项说明

### 3.1 常用选项

| 选项 | 说明 |
|------|------|
| `--workspace` | 运行整个 workspace 的所有测试 |
| `--package <name>` | 只运行指定包的测试 |
| `--lib` | 只运行库测试（不包括集成测试） |
| `--tests` | 只运行集成测试 |
| `--doc` | 运行文档测试 |
| `--release` | 使用 release 模式运行测试（更快但编译慢） |
| `--no-fail-fast` | 即使有测试失败也继续运行其他测试 |

### 3.2 测试过滤

```powershell
# 运行名称包含 "item" 的测试
cargo test item

# 运行名称包含 "golden" 的测试
cargo test golden

# 排除某些测试
cargo test -- --skip slow_test
```

### 3.3 并行和线程控制

```powershell
# 单线程运行（用于调试）
cargo test -- --test-threads=1

# 指定线程数
cargo test -- --test-threads=4
```

## 四、客户端相关测试

### 4.1 当前客户端测试状态

**注意**：客户端相关的 crate（`crystal-client-*`）目前还没有测试。

### 4.2 建议添加的测试

#### 单元测试
- `crystal-client-config` - 配置加载/保存测试
- `crystal-client-net` - 网络连接/重连测试
- `crystal-lib` - Lib 文件解码测试
- `crystal-client-asset` - 资产加载测试

#### 集成测试
- `crystal-client-bin` - 端到端测试（登录流程等）

### 4.3 添加测试示例

#### 在 `crystal-client-config` 中添加测试：

```rust
// crystal-client-config/src/lib.rs 或 model.rs

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_config_default() {
        let cfg = ClientConfig::default();
        assert_eq!(cfg.network.server_addr, "127.0.0.1:7000");
    }

    #[test]
    fn test_config_load_save() {
        let mut cfg = ClientConfig::default();
        cfg.network.server_addr = "192.168.1.1:8000".to_string();
        
        let path = std::env::temp_dir().join("test_config.toml");
        cfg.save(&path).unwrap();
        
        let loaded = ClientConfig::load_or_default(&path).unwrap();
        assert_eq!(loaded.network.server_addr, "192.168.1.1:8000");
    }
}
```

#### 在 `crystal-client-net` 中添加测试：

```rust
// crystal-client-net/src/lib.rs 或 client.rs

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_reconnect_strategy() {
        let mut strategy = ReconnectStrategy::new(5, 1000, 10000, 2.0);
        assert!(strategy.should_reconnect());
        
        for _ in 0..5 {
            strategy.record_attempt();
        }
        assert!(!strategy.should_reconnect());
    }

    #[test]
    fn test_network_metrics() {
        let metrics = NetworkMetrics::new();
        metrics.record_sent(100);
        metrics.record_received(200);
        
        assert_eq!(metrics.bytes_sent(), 100);
        assert_eq!(metrics.bytes_received(), 200);
    }
}
```

## 五、Golden Tests 说明

### 5.1 什么是 Golden Tests

Golden tests 是一种对比测试方法：
1. 运行代码生成输出
2. 与预先保存的"黄金标准"输出对比
3. 如果不同，测试失败（或更新黄金标准）

### 5.2 运行 Golden Tests

```powershell
# 运行所有 golden tests
cargo test --package crystal-server-core golden

# 运行特定的 golden test
cargo test --package crystal-server-core golden_drops
```

### 5.3 更新 Golden Files

当业务逻辑改变导致输出变化时，需要更新 golden files：

```powershell
# 设置环境变量（具体变量名查看测试文件）
$env:UPDATE_GOLDEN="1"
cargo test --package crystal-server-core golden_drops

# 或者直接删除旧的 golden file，让测试重新生成
```

## 九、常见问题

### 9.1 测试找不到文件

**问题**：测试需要读取文件，但路径不对

**解决**：
- 使用相对路径时，确保从项目根目录运行
- 或使用 `std::env::current_dir()` 检查当前目录
- 考虑使用 `include_str!` 或 `include_bytes!` 宏嵌入测试数据

### 9.2 测试依赖外部资源

**问题**：测试需要网络连接或数据库

**解决**：
- 使用 mock 对象
- 使用测试专用的测试数据
- 标记为 `#[ignore]` 并在 CI 中单独运行

### 9.3 测试运行太慢

**解决**：
- 使用 `--release` 模式（编译慢但运行快）
- 使用 `--test-threads` 控制并行度
- 将慢测试标记为 `#[ignore]` 并单独运行
